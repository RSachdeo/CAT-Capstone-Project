Locator Strategy

Preferred (Most Stable)

  • data-qa attributes
  • Semantic selectors (roles)
  • Text-based locators
// Good - Stable
page.locator('[data-qa="login-button"]')
page.getByRole('button', {name: 'Submit'})
page.getByText('Add to Cart')

Avoided (Fragile)

  • XPath expressions
  • CSS class selectors
  • Complex DOM paths
// Avoid - Fragile
page.locator('.btn-primary')
page.locator('//div[3]/button')
page.locator('#app > div > form')

Accessibility Testing

axe-core Integration

  • WCAG 2.0/2.1 compliance
  • Automated a11y scans
  • Detailed violation reports
  • Severity classification
import AxeBuilder from '@axe-core/playwright';

const results = await new AxeBuilder({ page })
  .withTags(['wcag2a', 'wcag2aa'])
  .analyze();

// Check for critical violations
expect(results.violations
  .filter(v => v.impact === 'critical')
).toHaveLength(0);

Key Design Decisions

Why Playwright?

  • Modern, fast execution
  • Auto-wait mechanism
  • Built-in cross-browser
  • Excellent TypeScript support
  • Rich debugging tools

Why Page Object Model?

  • Maintainability
  • Reusability
  • Readability
  • Single point of change
  • Team scalability

Framework Scalability

  • Easy to add new pages and tests
  • Modular utilities for common operations
  • Data-driven approach for test variations

Challenges & Solutions

Challenge Solution
Ads blocking test execution Network interception to block ad requests
Flaky element detection Stable locators (data-qa, roles, text)
Dialog/Alert handling Event listeners for dialogs
Multiple matching elements .first(), .nth(), more specific selectors
Slow page loads Custom waitForPageLoad(), increased timeouts
Test data cleanup Delete account in teardown
